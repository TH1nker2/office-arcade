# 摸鱼游戏厅 · 开发者手册

> 面向**接手这个项目的下一位开发者**。读完这份文档，你应该能：
> 跑起来、看懂代码、改一个 bug、加一个游戏、发一个版。
>
> 配套文档：[README.md](../README.md)（使用者视角）、[发版流程.md](发版流程.md)（发布操作）。

## 一、这是个什么项目

一个**零依赖**的局域网多人小游戏平台。同事们打开同一个网址，各自登录，进房间，一起玩 6 款小游戏。

**技术栈就三样**：Node.js 内置模块、原生浏览器 API、SQLite。

| 层 | 用什么 | 为什么 |
| --- | --- | --- |
| 服务端 | 纯 `node:*` 内置模块 | 内网部署，不想让运维装依赖；拷过去就能跑 |
| 实时通信 | 手写 WebSocket（RFC 6455 子集） | 同上，省掉 `ws` 包 |
| 存储 | `node:sqlite`，失败时退化为 JSON | Node 22+ 自带，不需要 `better-sqlite3` 编译 |
| 前端 | 原生 DOM + Canvas 2D | 没有构建步骤，改完刷新就生效 |
| 打包 | PowerShell + Python `tarfile` | 生成带运行时的免安装包 |

**这些约束是刻意的，改之前先想清楚**：不要引入 npm 依赖、不要引入打包器、不要引入前端框架。整个仓库的依赖项数量是 **0**，这是它能被随便拷进内网的前提。

## 二、十分钟跑起来

```bash
# 1. 需要 Node 22+（node:sqlite 从 22 开始有）
node -v

# 2. 源码运行（第一次需要下载运行时，或者直接用系统 node）
node server.js 8090

# 3. 浏览器打开
http://localhost:8090
```

管理员后台 `/admin.html`，账号在根目录 `admins.json`（明文，改完重启生效）。
仓库里那份是示例；**发行包每次打包会随机生成密码**并写进 `首次使用.txt`。
后台顶部有「玩家管理 / 你画我猜词库 / 谁是卧底词库」三个页签；画猜页按难度只读展示 500 个词和 4 条提示，卧底页按分类只读展示 120 对相近词，均支持搜索。
对应接口是 `GET /api/admin/words?level=easy|normal|hard` 和 `GET /api/admin/undercover-words`，未登录会返回 401。

**数据在哪**：程序目录下的 `data/arcade.sqlite`。删掉 `data/` 就是重置。
也可以用 `ARCADE_DATA=/tmp/x node server.js` 临时换目录（测试脚本都这么干）。

## 四、一次对局的完整数据流

这是理解整个项目的关键，建议对照代码读一遍。

```
  浏览器                         服务器
    │                              │
    │ 1. WS 连接 /ws?token=...     │  握手时用 sid Cookie 鉴权
    │─────────────────────────────▶│
    │                              │
    │ 2. {t:'createRoom',gameId}   │  createRoom()
    │─────────────────────────────▶│    → rooms.set(code, room)
    │◀─────────────────────────────│  广播 {t:'room'}
    │                              │
    │ 3. {t:'start'}               │  startRound()
    │─────────────────────────────▶│    AR.games[id].create(players)
    │                              │    room.phase = 'playing'
    │                              │
    │         ┌────────────────────┴────────────────┐
    │         │  游戏循环：每 8ms 醒一次            │
    │         │  while (acc >= 1/60) {              │
    │         │    人机决策 → g.input()             │
    │         │    g.tick(1/60)                     │
    │         │  }                                  │
    │         │  按 g.rate 发 {t:'state', s:快照}   │
    │         └────────────────────┬────────────────┘
    │                              │
    │ 4. {t:'input', i:{...}}      │  客户端每 33ms 发一次
    │─────────────────────────────▶│    → g.input(game, id, i)
    │◀─────────────────────────────│  快照（30-60Hz）
    │                              │
    │ 5. g.isOver() 为真           │  finishRound()
    │◀─────────────────────────────│   {t:'over', res:[...]}
    │                              │   写 matchAdd() → 数据库
```

**要点**：

1. **客户端不算游戏逻辑**。它只把键鼠状态打包发上去，然后把收到的快照画出来。改游戏平衡只改 `shared/games/`。
2. **浏览器也加载 `shared/core.js` 和 `shared/registry.js`**——注册表里的元信息（人数、描述、图标）前端直接用，避免两头维护。
3. **快照是完整的，不是增量的**。每个 state 都是当前画面的全量描述，客户端直接覆盖。牺牲带宽换简单，内网完全够用。

## 五、游戏模块契约（加新游戏看这里）

每个游戏是 `AR.games.<id>` 上的一个对象。**必须实现**：

```js
AR.games.foo = {
  id: 'foo',

  // 创建对局状态。players = [{id, name, color, bot?}]
  create(players, opt) { return state; },

  // 玩家操作。inp 的内容自己约定（见各自 input.js 分支）
  input(state, playerId, inp) { },

  // 推进一帧。dt 永远是 1/60
  tick(state, dt) { },

  // 是否结束（服务端每帧问一次）
  isOver(state) { return state.ended; },

  // 结算：[{id, name, score, ...}]，服务端写进战绩
  results(state) { return [...]; },

  // 发给所有客户端的状态（必须可 JSON 序列化）
  snapshot(state) { return {...}; },

  // 可选：人机决策，返回一个 input 对象或 null
  bot(state, playerId, dt, level) { },

  // 可选：快照频率（默认 60）
  rate: 60,

  // 可选：只发给某个玩家的私有数据（你画我猜的选词用）
  privateFor(state, playerId) { },

  // 可选：玩家中途退出
  removePlayer(state, playerId) { }
};
```

谁是卧底的私有消息用 `privateFor` 只下发自己的身份和词；词对在 `shared/undercover-words.json`，由 `server/undercover-words.js` 加载并校验。

然后在 `shared/registry.js` 里登记一行：

```js
{ id: 'foo', name: '某某大作战', sub: 'FOO ARENA', icon: '🎯',
  min: 2, max: 4, time: 90, tag: '对战', desc: '一句话玩法',
  hint: '操作提示' }
```

最后在 `js/render/<game>.js` 加一个 `R.foo = function (ctx, w, h, s, dt, G) {...}`，
在 `js/ui.js` 的 HUD 分支里加对应的分数展示，在 `js/input.js` 加按键收集。

**检查清单**：

- [ ] `create` 里所有坐标都用逻辑坐标（自己定一个画布尺寸，绘制时 `fit()`）
- [ ] 快照里的数字都是有限的（`NaN` 会让前端整屏崩）
- [ ] `isOver` 一定会变成 true（否则这局永远不结束）
- [ ] `tick` 是纯函数式的：只改 state，不读时间、不读文件、不发网络请求
- [ ] 人机在 `tick` 循环里被调用，所以 `bot` 里不要再调 `tick`
- [ ] 跑一遍 `node tools/game-test.js` 和 `node tools/bot-test.js`

## 六、快照与频率

| 游戏 | 频率 | 说明 |
| --- | --- | --- |
| 坦克 / 弹幕 | 60 Hz | 连续运动，需要平滑 |
| 俄罗斯方块 | 30 Hz | 方块有下落节拍 |
| 你画我猜 / 谁是卧底 | 10 Hz | 你画我猜笔迹靠事件，快照只带计时；谁是卧底是回合制，私有消息发身份和词 |
| 五子棋 | 8 Hz | 回合制 |

**模拟永远是 60 Hz 固定步长**，跟快照频率无关。

带宽量级（实测）：60Hz 下 4 人坦克房服务器上行约 400–800 KB/s，单人下行 20–100 KB/s。内网不用担心，但**如果加的游戏快照特别大**（比如每帧发整张地图），记得先量一下。

## 七、存储层

```
shared/store.js            ← 统一入口，别的地方只用它
      ├── store-sqlite.js  ← 有 node:sqlite 时用这个
      └── store-json.js    ← 退化方案（文件锁/只读时）
```

**接口**（两套实现必须一致）：

```
createUser / userById / userByName / userByNickname / updateUser / deleteUser
listUsers / topUsers
sessionCreate / sessionGet / sessionDelete / sessionDeleteByUser / sessionCleanup
matchAdd / matchesByUser
stats
```

**迁移**：`store-sqlite.js` 里用 `PRAGMA user_version` 做版本号，`MIGRATIONS` 数组按顺序执行。
加字段时：`SCHEMA_VERSION` +1，往 `MIGRATIONS` 里加一条，**不要改已有的迁移**。

**注意**：这个项目的数据库曾经出过 "attempt to write a readonly database"，
所以现在 `open()` 里有一道**写探针**（`BEGIN IMMEDIATE; ROLLBACK`），
失败会自动清理 `-wal`/`-shm` 再重开一次。改存储层时别把它删了。

如果 `node:sqlite` 存在但数据库打开失败，程序会直接退出，不会回退 JSON；只有模块本身不可用或显式 `ARCADE_STORE=json` 才使用 JSON，避免产生两套账号数据。

## 八、前端结构

### 状态

`js/state/app-store.js` 里的 `APP`（也就是 `AR.App`）是唯一的状态源：

```js
APP.screen   'auth' | 'lobby' | 'play'
APP.me       当前用户
APP.room     当前房间（服务端下发的）
APP.game     当前对局元信息
APP.snap     最新快照（渲染直接读它）
```

**界面永远由服务端消息驱动**。不要在本地"猜"房间状态——服务端每次都会推 `room`。

### 玩家右键菜单与资料卡

大厅玩家行带 `data-user-id`；右键先弹出 `#player-menu` 操作菜单，选项集中定义在 `ui.js` 的 `PLAYER_MENU_ITEMS`：
每项支持 `icon`、`divider`（分组线）和 `when(user)`（条件显示）。当前只有「查看资料」。
点击后再通过 `GET /api/players/:id` 拉取公开资料、在线/房间状态和最近 10 局，渲染到 `#player-overlay`。
接口只返回 `publicUser` + 战绩，不返回密码哈希、盐或会话令牌。右键自己时显示「编辑我的资料」。
菜单会跟随视口边缘收口，并在点击外部、滚动、resize、Esc、切换界面时关闭。

### 覆盖层可访问性

`js/ui/a11y.js` 统一监听 `.overlay` 的显示/隐藏：打开时把焦点移入第一个可操作元素，Tab 在层内循环，关闭时还原到打开前的元素。新增弹层沿用 `.overlay` + `hidden` 类即可自动获得焦点管理；不要手工在别处抢焦点。
玩家行支持 Enter/空格打开操作菜单，菜单内支持方向键、Home/End、Enter/空格，Esc 关闭并把焦点还给玩家行。

### 覆盖层动画

结算层 `#over-overlay` 的显示/隐藏统一走 `ui.js` 的 `showOver() / hideOver()`：
先切换 `.is-open` 触发 CSS 淡入淡出，淡出结束后才加回 `.hidden`。
**不要直接对它 `classList.add/remove('hidden')`**，否则会绕过动画、回到瞬间跳出的旧行为。
其他覆盖层（邀请、排行榜、确认框等）仍保持原来的即时开关。

### 渲染

`js/main.js` 每帧调用：

```js
UI.tick(dt);                                  // 更新文本、类名（便宜操作）
AR.Render.render(ctx, w, h, gameId, snap, dt, G);  // 画游戏
```

`render.js` 里所有游戏的绘制函数签名都是 `(ctx, w, h, s, dt, G)`：
`s` 是快照，`G` 是玩家列表等元信息。

**逻辑坐标 vs 屏幕坐标**：每个游戏自己定一个逻辑画布（比如五子棋 15×15 格），
用 `fit(w, h, WW, WH)` 换算。命中测试要用**同一个** `fit` 把鼠标换回去，否则点不中。

### 输入

`js/input.js` 收集键鼠状态，`main.js` 每 33ms 打包一次发上去。
不同游戏收集的内容不同（坦克是 WASD+瞄准，俄罗斯方块是按键事件），
具体在 `AR.Input.collect(gameId)` 里分支。

大厅聊天在 `ui.js` 里额外监听 Enter：仅在大厅、没有弹窗、焦点不在输入框/按钮上时，聚焦 `#lobby-chat-text`；
输入框聚焦后 Enter 由它自己的 keydown 负责发送。

## 九、WebSocket 协议速查

完整清单在 `server.js` 文件头的注释里。几个容易踩的点：

- **必须带 Cookie**：`/ws` 握手用 `sid` Cookie 鉴权，没有就 401。`?token=` 只在本机 loopback（测试/脚本）下兼容，远程连接必须用 Cookie。
- **消息上限 256KB**：超了直接断开连接。
- **同一个账号只保留最新连接**：在第二个标签页登录会把第一个顶掉。
- **频道**：大厅广播 `{t:'lobby'}` 和房间广播 `{t:'room'}/{t:'state'}` 是分开的。

**改服务端网络/静态/渲染**：加跑 `hardening-test`，必要时跑 `perf-test` 对比帧时间。
`perf-test` 目前只测坦克、俄罗斯方块、弹幕三款高帧率游戏；画猜/五子棋/卧底快照频率较低，未纳入 RAF 基线。

所有测试都是自包含的：自己起服务器（随机端口 + 临时数据目录），跑完自己清理。

## 十一、发版

完整步骤（测试、打版本号、构建、Gitee 发布、GitHub 镜像、验证）见 [发版流程.md](发版流程.md)。
发版完成后同步 GitHub 代码与 tag：`git push github main && git push github --tags`。
tag 推送会自动触发 `mirror-release-assets` 工作流，把本次 Gitee 的三个安装包镜像到 GitHub Release；推送门禁同样适用。

**三个坑**（都踩过）：

1. **Gitee 附件配额 1 GB**。每个版本约 117 MB。`publish-release.ps1` 默认只做配额预检，超过 900 MB 会停止；只有显式 `-PruneOldReleases` 才清理旧附件，而且只删附件、不删发行版页面，默认保留最近 3 个版本。
2. **`.bat` 里不能有中文**。cmd 按控制台代码页逐字节解析批处理，中文被拆开后剩下的半句会被当成命令执行，报 `xxx is not recognized`。打包脚本现在会校验，含非 ASCII 字节直接构建失败。
3. **`build-release.ps1` 必须存成 UTF-8 带 BOM**。`powershell.exe`（5.1）没有 BOM 时按 ANSI 读脚本，中文注释会变乱码导致语法错误。

## 十二、常见坑与设计取舍

| 现象 | 原因 | 怎么处理 |
| --- | --- | --- |
| `attempt to write a readonly database` | 残留 `-wal`/`-shm` 或旧进程占着文件 | 已加写探针自动修复；实在不行删掉 `-wal`/`-shm` 重启 |
| 玩家说"点不中飞机/棋子" | 命中测试的循环上限写死，或者 `fit` 参数和绘制不一致 | 检查 `R.*HitTest` 里的循环边界 |
| 播报出现奇怪的字（"击毁到家"） | 用了 `x \|\| '默认值'`，空串被当成缺省 | 判 `=== undefined` 而不是 `\|\|` |
| 修改后没有任何变化 | 改的是服务端文件但没重启 | `server.js` / `shared/` 改动必须重启；`js/` `css/` 刷新即可 |
| 改名后聊天/邀请仍显示旧名字 | WebSocket 连接缓存了 `conn.user`，资料更新没同步 | `/api/profile` 更新后同步 `presence` 里连接的 `conn.user` |
| 数据"丢了" | 在别的目录启动了服务 | 数据固定跟着程序目录的 `data/`，看启动横幅打印的路径 |

**几个刻意的取舍**：

- **快照全量而非增量** —— 简单、不会状态错乱，代价是带宽。
- **服务端权威** —— 客户端不做预测，操作会有 1 个 RTT 的延迟感，换来零作弊和零不同步。
- **无构建步骤** —— 直接写 ES5 风格 JS，任何浏览器都能跑，代价是没有模块化和 tree-shaking。
- **房间无持久化** —— 进程重启 = 所有房间消失，只有账号和战绩落库。

## 十三、代码风格

- **ES5 风格**：前端用 `var` 和 `function`，不用箭头函数/`let`/`const`（服务端可以用 `const`/`let`，因为只有 Node 跑）。这样做是为了不依赖任何转译。
- **中文注释**，面向中文读者；标识符一律英文。
- **一个文件一个职责**，宁可长也不要拆得零碎（`js/ui.js` 作为界面入口刻意保持集中，具体功能在 `js/ui/` 下）。
- **不用分号省略**，统一加分号。
- **缩进 2 空格**。

## 十四、如果你想加一个功能

按这个顺序做，一般不会踩坑：

1. **先想清楚状态在谁那里**。游戏内的东西放 `state`，房间级的东西放 `room`，界面级的东西放 `APP`。
2. **改服务端**：在 `server/ws.js` 加消息分支 → 广播新消息类型。
3. **改前端**：`ui.js` 订阅这个消息 → 更新 DOM/`APP`。
4. **写测试**：至少覆盖新分支的正反两种情况。
5. **跑全套测试** → 更新 README（如果影响了使用者）。
6. **加注释**：说明"为什么这么做"，而不是"这行在做什么"。
