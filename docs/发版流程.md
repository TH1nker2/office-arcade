## 阶段 0 · 一次性环境准备（每台开发机只做一次）

开发环境（clone、`runtime/`、`admins.json`、启动）见 [开发手册 §二](开发手册.md#二十分钟跑起来)。

发版额外准备三平台运行时（约 230 MB，之后复用）：

```bash
powershell -ExecutionPolicy Bypass -File tools/fetch-runtime.ps1 -Target win-x64,linux-x64,darwin-arm64

# 可选：配置 GitHub 私有镜像（需要你自己的 GitHub 凭据）
git remote add github https://github.com/TH1nker2/office-arcade.git
```

**这几样永远不会进仓库**：

| 路径 | 说明 |
| --- | --- |
| `runtime/` | 本机 Node 运行时 |
| `vendor/` | 多平台打包用的运行时缓存 |
| `dist/` | 构建产物 |
| `data/` | 玩家数据库 |
| `admins.json` | 管理员明文密码 |

## 阶段 1 · 日常开发

```bash
# 改代码后起服务看效果
runtime/node.exe server.js

# 测试矩阵见开发手册 §十；日常至少跑全量非浏览器测试
node tools/test-all.js
```

### 改哪里

调度关系一句话：**`shared/` 是服务端权威模拟，`js/` 只负责发输入和渲染。**

| 想改的东西 | 改哪里 |
| --- | --- |
| 游戏规则、物理、AI | `shared/games/*.js` |
| 新增一款游戏 | `shared/games/xxx.js` + `shared/registry.js` + `server.js` 里 require |
| 画面、动画 | `js/render/<game>.js`，公共工具在 `js/render/common.js` |
| 大厅、房间、聊天界面 | `js/ui/*.js` + `js/ui.js` + `index.html` + `css/*.css` |
| 后端接口、房间逻辑 | `server/http.js` / `server/rooms.js` |
| 管理后台 | `admin.html` + `js/admin.js` + `shared/admin-api.js` |
| 你画我猜词库 | `shared/words.json` |
| 谁是卧底词库 | `shared/undercover-words.json` |

### 版本号什么时候动

只有**应用行为变了**才需要打新版本号（阶段 2 第 ② 步）。
纯文档、纯注释、纯测试脚本的改动，提交推送即可，不用发版。

## 阶段 2 · 发版（七步，顺序不能乱）

```bash
# ① 测试全绿 + 文档同步
node tools/test-all.js --with-ui
# 涉及渲染/性能再加：node tools/perf-test.js
# 测试矩阵见 docs/开发手册.md §十

# ② 打版本号：旧版本自动归档进 version.json 的 history
runtime\node.exe tools\bump-version.js 3.1.0 "这次改了什么" "还改了什么"

# ③ 提交
git add <相关文件>
git commit -m "feat: ..."

# ④ 先推送   ← 关键
git push

# ⑤ 构建三平台包 + 建发行版 + 上传（默认不删旧页面）
$env:GITEE_TOKEN="你的私人令牌"
powershell -ExecutionPolicy Bypass -File tools\publish-release.ps1

# ⑥ 把发行版自动创建的 tag 拉回本地
git fetch --tags

# ⑦ 同步 GitHub 代码与 tag
#    tag 推送会自动触发 mirror-release-assets 工作流，
#    从 Gitee 下载本次三个包并上传到 GitHub Release
git push github main
git push github --tags
```

### 为什么第 ④ 步必须在 ⑤ 之前

`publish-release.ps1` 让 Gitee 在 **`main` 的 HEAD** 上打 tag。
本地提交还没推送的话，tag 会打在旧提交上，发行版里的源码就和版本号对不上了。

脚本里已经有保护：`HEAD` 和 `origin/main` 不一致会直接报错，不会静默发错。

### GitHub 镜像怎么推

GitHub 仓库 `TH1nker2/office-arcade` 是私有镜像：代码与 tag 手动推，安装包由 tag 推送触发的 Actions 自动镜像。

- 首次在一台机器上：`git remote add github https://github.com/TH1nker2/office-arcade.git`
- 凭据用你自己的 GitHub PAT / 凭据管理器，**不要把令牌写进 remote URL**
- 日常代码推送：`git push`（Gitee）后补 `git push github main`
- 发版后：`git fetch --tags`，再 `git push github main` 和 `git push github --tags`
- 推送 tag 会触发 `.github/workflows/mirror-release-assets.yml`：
  - 从 Gitee 下载本次三个安装包
  - 创建/复用 GitHub Release
  - 用 `gh release upload` 上传，**不需要本地上传**
- 手动补镜像：GitHub → Actions → `mirror-release-assets` → Run workflow，输入 tag
- 本地 `main` 的上游保持 `origin/main`（Gitee），不要把上游改成 `github/main`

### Gitee 附件配额与旧版本清理

Gitee 免费仓库的附件总配额约 **1 GB**，每个便携版三平台包约 **117 MB**。

`publish-release.ps1` 现在的规则：

- **默认绝不删除任何发行版页面**
- 上传前统计 Gitee 全部附件 + 本次安装包的总量
- 超过 `-QuotaLimitMB`（默认 900 MB）时**停止并提示**，不会静默清理
- 只有显式传 `-PruneOldReleases` 才清理旧附件
- 清理只删除安装包附件，**发行版页面和说明永久保留**
- 默认保留最近 `-KeepVersions 3` 个版本的安装包
- 删除前会检查 GitHub Release 是否已有对应安装包；缺少 `GITHUB_TOKEN` 或资产不足时跳过该版本
- 删除前打印清单并要求输入 `YES` 确认；`-Force` 可跳过确认，但只应在明确知道影响时使用

示例：

```bash
# 只打印计划，不调任何接口
powershell -ExecutionPolicy Bypass -File tools\publish-release.ps1 -DryRun

# 只读预检：查询 Gitee 配额和清理候选，不创建/上传/删除
powershell -ExecutionPolicy Bypass -File tools\publish-release.ps1 -CheckOnly
powershell -ExecutionPolicy Bypass -File tools\publish-release.ps1 -CheckOnly -PruneOldReleases

# 配额超限后，显式清理旧附件（会先列出清单并要求确认）
powershell -ExecutionPolicy Bypass -File tools\publish-release.ps1 -PruneOldReleases
```

### 第 ⑤ 步内部做了什么

```
version.json 读出版本号 v3.1.0
      │
      ▼
build-release.ps1
      ├─ win-x64      → office-arcade-v<版本>-win-x64.zip
      ├─ linux-x64    → office-arcade-v<版本>-linux-x64.tar.gz
      └─ darwin-arm64 → office-arcade-v<版本>-darwin-arm64.tar.gz
      3 个平台各一个包（都是便携版：数据在包内 data\）
      每个包 = 运行所需源码（server.js / server / shared / js / css / 页面 / version.json）
               + 该平台 runtime/node + 对应平台启动器 + LICENSE
               + 随机密码的 admins.json + 首次使用.txt
      tools/、docs/、memory.md、README.md、package.json、CI 配置不进包
      产物清单写进 dist/SHA256SUMS.txt
      │
      ▼
publish-release.ps1
      ├─ 配额预检（默认不删页面；-PruneOldReleases 才清理旧附件）
      ├─ dist/release-notes.md 不存在时按 version.json 自动生成
      ├─ POST /releases          建发行版（tag v3.1.0）
      └─ POST /attach_files × 3  逐个上传
```

### 首次发版多一步

打包要三个平台的运行时，得先下到 `vendor/`（**约 230 MB，之后一直复用**）：

```bash
powershell -ExecutionPolicy Bypass -File tools\fetch-runtime.ps1 -Target win-x64,linux-x64,darwin-arm64
```

### 关于 tar.gz 和可执行位

Unix 包靠 python 的 `tarfile` 显式设 `0755` 来保留可执行位（Windows 的 `tar.exe` 打出来的全是 0644）。
机器上没有可用 python 时会退回 `tar.exe`，解压后需要：

```bash
chmod +x runtime/node start.sh
```

`start.sh` 自带自愈逻辑，会尝试自己补权限，但不保证一定成功。

## 阶段 3 · 验证发行版

```bash
# 看清单
cat dist/SHA256SUMS.txt

# 抽一个包下载回来核对
curl -LO https://gitee.com/th1nker/office-arcade/releases/download/v3.1.0/office-arcade-v3.1.0-win-x64.zip
certutil -hashfile office-arcade-v3.1.0-win-x64.zip SHA256   # Windows
shasum -a 256 office-arcade-v3.1.0-win-x64.zip               # macOS / Linux
```

Windows 包还建议解压后直接跑一遍，确认 `/api/version` 返回的是新版本号。

## 一张图记住整条链路

```
开发者                              Gitee                        用户
──────                              ─────                        ────
git clone ──────────────►  源码仓库（只含源码，~7 MB）
   │                              │
   │ 改代码 / 测试                 │
   ▼                              ▼
bump-version ──► version.json    commit + push ──► main
   │
   ▼
build-release ──► dist/*.zip,*.tar.gz（3 个包，~117 MB）
   │
   ▼
publish-release ────────►  发行版 v3.1.0  ──────────►  下载对应平台的包
                            ├─ win-x64.zip               │
                            ├─ linux-x64.tar.gz          ▼
                            └─ darwin-arm64.tar.gz   解压 → 双击启动
                                                     → 发局域网地址给同事
```

GitHub 私有镜像：代码与 tag 用 `git push github main && git push github --tags` 同步；tag 推送会自动触发 Actions 把 Gitee 安装包镜像到 GitHub Release。

## 常见情况怎么处理

| 情况 | 做法 |
| --- | --- |
| 发包发到一半失败 | **直接重跑第 ⑤ 步**。脚本会复用已存在的发行版、跳过已上传的附件，不会重复传 |
| 已经把 v3.1.0 发了，发现包里缺文件 | 打 `2.8.1` 重新发。**同名附件不能覆盖**，想替换得先去网页上删掉那个附件 |
| 只想改文档 | 只做 ③④，跳过 ②⑤ |
| GitHub 代码/tag 没同步 | 补 `git push github main` 和 `git push github --tags` |
| GitHub 安装包没镜像 | 到 Actions 手动运行 `mirror-release-assets`，输入 tag |
| Gitee 附件接近 1 GB | 先确认 GitHub Release 已有归档，再用 `publish-release.ps1 -PruneOldReleases`；只删旧附件，页面保留 |
| 本地没有 python | 打包退回 `tar.exe`，Unix 包解压后要 `chmod +x`；装个 python 就没这问题 |
| 想升级 Node 版本 | 改 `tools/runtime-manifest.json` 的版本号 + 三个 `sha256`，再 `fetch-runtime.ps1 -Force` |
| 只发某个平台 | `build-release.ps1 -Target win-x64` |
| 只想看会做什么，不动远程 | `tools\publish-release.ps1 -DryRun` |
| 已经构建过，只想重传 | `tools\publish-release.ps1 -SkipBuild` |

---

## 一句话总结

**源码在 git 里，二进制在发行版里。**

开发者 clone 下来先拉一次运行时就能跑；发版时 `bump → commit → push → publish` 四板斧，
三平台包由脚本按白名单从同一份源码 + `vendor/` 里的三个运行时拼出来（开发文件不进包）。
